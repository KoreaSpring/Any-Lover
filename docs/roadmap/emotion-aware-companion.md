# 情感感知伴侣：情绪识别闭环 + 多模态输入

> 目标：让桌宠「感知用户情绪」并据此调整**回复语气**与**角色表情**，形成情感闭环；同时在用户提问时把**桌面截屏 + 音频截取**一并作为上下文喂给大模型分析。
>
> 定位：本特性是方案甲（THA 桌宠，见 `easyvtuber-integration.md`）之后的**进阶方向**，分阶段渐进落地，不阻塞方案甲主线。

---

## 0. 与现有能力的关系（复用 vs 新增）

Any-Lover 现有基建（前端 `renderer/src/context/`）：
- ✅ `screen-capture-context.tsx`：屏幕捕获（`getDisplayMedia` + Electron `get-screen-capture`）——**截屏能力现成**。
- ✅ `camera-context.tsx`：摄像头。
- ✅ `vad-context.tsx`：语音活动检测（VAD）。
- ✅ 后端上游本就输出**情绪标签**驱动 Live2D 表情；LLM 配置支持线上 API / Ollama（对话模型可换）。
- ✅ 内置 `minicpm-v` 多模态，支持图片输入（README 的「看屏幕/摄像头」）。

需要新增：文字情绪判定与注入、语音 SER、面部 MediaPipe、三模态融合、情绪→语气/pose 的双向下发、多模态输入打包。

## 1. 情绪识别闭环（三步渐进）

### 第一步：文字情绪（零新增模型，先跑通闭环）

- **做什么**：LLM 读当前对话内容，判定用户情绪（语义层面），并据此调整回复语气；同时产出一个情绪标签用于驱动角色表情。
- **实现**：
  - 在发给 LLM 的系统提示里加入指令：分析用户情绪，回复时用合适语气，并在结构化输出里带一个情绪字段（如 `{"emotion":"sad","reply":"..."}`）或沿用上游已有的情绪标签机制。
  - 情绪字段 → 映射 THA pose（见 `easyvtuber-integration.md` §4 情绪→pose 映射表）。
- **成本**：零额外模型，改 prompt / 输出解析即可。**先做这步跑通完整闭环**。

### 第二步：语音 SER（轻量 ONNX，"听语气"，输出 VAD）

- **做什么**：从用户说话的**声调/语速/能量**判情绪，捕捉"语气里的情绪"（同一句话委屈还是平静）。
- **模型**：轻量 SER ONNX，走 onnxruntime（几十 MB，甚至有 72K 参数蒸馏版）。输出建议用 **VAD 连续维度**（Valence 效价 / Arousal 唤醒 / Dominance 支配），比离散标签细腻。
  - 参考：[wav2vec2-emotion-recognition-ONNX](https://huggingface.co/onnx-community/wav2vec2-emotion-recognition-ONNX)、[voice_emo (VAD)](https://huggingface.co/muqtadar/voice_emo)、[Wav2Small 72K](https://arxiv.org/abs/2408.13920v3)。
- **实现**：复用 VAD 采集到的用户音频片段 → SER 推理 → VAD 数值。可放后端（Python onnxruntime）或前端（onnxruntime-web）。
- **为何对 Any-Lover 价值大**：本就是语音对话应用，麦克风音频现成；语音情绪对陪伴体验的增益常大于看脸，且**不需要摄像头**、隐私更好。

### 第三步：面部 MediaPipe（可选，摄像头开时）+ 三模态融合

- **做什么**：摄像头开启时，用 MediaPipe Face Landmarker（几 MB，浏览器内 WASM，跨平台）出 blendshapes → 面部情绪；与文字、语音做 **late fusion**。
- **融合**：三路各产出 VAD/置信度，加权融合成综合情绪状态。任一路缺失（如没开摄像头）自动降级用其余路。
- **参考**：M3ER / MemoCMT / MELD 等多模态融合工作（内容已改写以符合引用规范）。
- **隐私**：摄像头默认关、显式授权、本地处理、不出机、有指示。

### 情绪结果的双向下发

```
融合情绪状态(标签 + VAD)
  ├─► 注入 LLM 上下文  → 回复语气适配（温柔安抚 / 轻快 / 认真…）
  └─► 映射 THA pose    → 角色表情适配（§4 情绪→pose 映射表）
```

## 2. 提问时的多模态输入采集（截屏 + 音频 + 情绪）

> 需求：用户提问时，把桌面截屏 + 音频截取一并作为信息输入给大模型分析。

### 采集内容

| 输入 | 来源 | 现状 |
| --- | --- | --- |
| 桌面截屏 | `screen-capture-context`（getDisplayMedia）抓一帧 | ✅ 能力现成，需在提问时触发单帧抓取 |
| 音频截取 | VAD 采集的本轮用户语音片段 | ✅ 采集现成，需转给 SER + 可选转给多模态模型 |
| 用户情绪 | 第 1 章融合结果 | 🔴 随情绪闭环一起做 |
| 文本 | 对话/ASR 转写 | ✅ 现成 |

### 组装与下发（提问触发）

1. 用户发起提问（语音说完/回车）。
2. 并行采集：抓一帧屏幕截图 + 取本轮音频片段 + 当前融合情绪状态。
3. 打包为一次多模态请求：
   - 文本（问题） + 图片（截屏） → 发给**支持视觉的** LLM；
   - 情绪状态作为系统上下文（如「用户此刻低落、看起来在看报错日志」）注入。
4. LLM 综合「问题 + 屏幕内容 + 用户情绪」生成带语气的回复 → TTS + THA 表情。

### 关键约束（务必写清，避免踩坑）

- **模型必须支持视觉**：截屏图片只有喂给多模态模型（minicpm-v / qwen-vl / llava 或支持视觉的线上 API）才有意义。若用户把对话模型换成**纯文本模型**，截屏会被忽略——需在设置里检测并提示，或自动降级为「只发文字」。这与 README「换非视觉模型时图片被忽略」的现有行为一致。
- **模型换线上/自建 Ollama**：对话/视觉模型可走线上 API 或自建 Ollama，改设置 base_url/model 即可（现有 `backend-manager` 已支持），无需内置大模型。
- **隐私（高优先）**：截屏 + 摄像头 + 麦克风都高度敏感。必须：默认关闭、每类能力独立显式授权、本地优先不上传第三方（除非用户选了线上 API 并知情）、有明确开关与采集指示、可一键关闭。截屏可能含敏感信息，发送前给用户可见提示/可取消。
- **性能/节流**：截屏与情绪推理按「提问触发」或低频（如每几秒）执行，不逐帧跑，避免占用。

## 3. 建议的落地顺序

1. **文字情绪闭环**（第一步）：prompt 注入 + 情绪字段 → 语气 + THA 表情。零新增模型。
2. **提问多模态输入**：接现有 `screen-capture` 抓帧 + 音频片段，随提问打包给视觉 LLM（先文字+截屏，情绪先用文字路）。
3. **语音 SER**（第二步）：加轻量 ONNX，输出 VAD，融入情绪状态。
4. **面部 MediaPipe + 三模态融合**（第三步，可选）：摄像头开时增强。
5. 全程情绪既注入 LLM 又驱动 THA pose，形成完整情感闭环。

每步都可独立上线、独立回退；摄像头/截屏等敏感能力全部默认关、用户可控。

## 5. 模型部署拓扑（方案 B 定稿）

目标硬件基准：**RTX 2060 6GB**。本地 GPU 首要给 THA（桌宠画面）用，显存预算紧张，因此模型分工如下：

### 分工

| 能力 | 跑在哪 | 选型 | 说明 |
| --- | --- | --- | --- |
| **桌宠画面** | 本地 GPU | EasyVtuber THA | 占 ~2–3GB（基础配置，少开/不开超分） |
| **对话主力 LLM** | **云端 API / 远程 Ollama（用户配置）** | 任意 OpenAI 兼容 / 远程 Ollama | 不占本地显存；能力强；`backend-manager` 现有配置已支持，改 base_url/model 即可 |
| **看屏幕视觉** | 本地 GPU（小模型，按需） | Moondream 2 (~2GB) 或 MiniCPM-V 4.6（边缘友好） | 只做截图/看屏，**按需触发**不常驻推理 |
| **情绪识别** | 本地 CPU/轻量 | 文字(零模型) + 语音 SER (ONNX 几十 MB) | 不与 THA 抢显存 |
| **联网搜索** | 本地服务 | SearXNG + MCP（见 §6） | 免费、无 key |

### 为什么对话走云端/远程（方案 B 而非全本地）

- 2060 6GB 装不下「强对话模型(7–8B) + THA」；本地小模型(如 MiniCPM-V 4.6 的 0.8B 语言底座)对话质量偏弱。
- 因此对话交给云端/远程（质量高、不占本地显存），本地只留**小视觉模型**看屏。
- **代价（如实记录）**：不再是「零配置开箱即用对话」——首次使用需用户配置云端 API 或远程 Ollama。安装包因此可不内置对话大模型，体积显著减小。

### 视觉「按需触发」= 省钱/省显存的关键

- 多数对话不需要看屏（闲聊/陪伴）。仅当：用户提到屏幕相关（"这个报错""看我的代码"）或手动点「让她看屏幕」时，才截屏 + 调视觉模型。
- 视觉调用从「每轮」降到「偶尔」，无论本地还是云端，成本都大幅下降。
- 本地小视觉模型日常免费兜底；需要高质量理解时可路由到云端多模态 API（可选分层）。

### 6GB 共存注意（需 Windows 实测）

- THA(2–3GB) + 本地小视觉模型(Moondream ~2GB / MiniCPM-V 4.6) 在 6GB 上**偏紧但可行**，峰值需在目标机实测。
- 备选：看屏幕时临时借显存、THA 短暂降档；或视觉也走云端只保留本地情绪轻模型。

### 打包体积预期（方案 B）

- 不内置 Ollama、不内置对话大模型；内置 THA 运行时 + 小视觉模型（或首启下载）。
- 估算：**约 2–5GB**，取决于 THA 走 ONNX(小) 还是 CUDA torch(大)、模型是否内置。乐观（ONNX + 模型首启下载）可压到 ~1.5–2GB。
- 明显小于「内置 minicpm-v 8B 整合版(7–9GB)」。
- 注：THA 运行时确切体积需 Windows 冻结后实测（CUDA torch 体积与版本强相关）。

## 6. 联网搜索：SearXNG + MCP（本地免费）

### 选型：SearXNG（自托管元搜索引擎）

- 开源、**完全免费、无 API key、无配额**；不自己爬网，而是把查询分发给 70+ 上游引擎（Google/Bing/DuckDuckGo/Brave/维基等）聚合结果，隐私友好。
- 相比付费搜索 API（Tavily/SerpAPI）无按量费用；相比直连 DuckDuckGo 更稳、可控、结果更全。

### 架构：搜索是「主力模型的工具」，不是模型自己联网

```
用户提问 → 主力LLM(云端/远程) 判断是否需要联网(function-calling)
   → 触发 SearXNG-MCP server → 查询分发多引擎 → 聚合结果/正文摘要
   → 回填上下文 → 主力LLM 综合生成回答
```

- LLM 不能自己联网；实际发请求的是**后端编排 + MCP 工具**。主力模型只负责「判断该不该搜 + 生成关键词 + 消化结果」。

### 与 Any-Lover 的契合（近乎即插即用）

- 上游后端**本就支持 MCP**（`conf.pet.yaml` 有 `use_mcpp` / `mcp_enabled_servers`）。
- 落地 = 跑一个 SearXNG 实例 + 注册一个 SearXNG-MCP server 进 `mcp_servers` 配置，主力模型即可通过 function-calling 联网。**不改后端核心代码**。
- 现成参考（内容已改写以符合引用规范）：`mcp-searxng` / `web-search-mcp-server` / `searxng-mcp`（后者带本地 ML 重排 + Ollama 查询扩展）。

### 部署与取舍

- SearXNG 用 Docker 或本地进程跑（Windows 亦可）。桌宠打包需考虑：随包内置 SearXNG（体验好、体积/复杂度增加）或引导用户本地部署（轻但需配置）。
- `use_mcpp` 默认关；联网作为可选能力，用户开启后生效。
- 隐私：SearXNG 不追踪查询；但搜索内容仍会发往上游引擎，需向用户说明。

## 7. 完整架构总览（本轮定稿）

```
                        ┌────────────── 主力 LLM（云端 API / 远程 Ollama，用户配置）──────────────┐
                        │  职责：对话大脑 + 决定是否联网/看屏 + 消化工具结果 + 输出情绪标签         │
                        └───────▲───────────────▲──────────────────▲───────────────▲────────────┘
     情绪状态(注入语气) ────────┘               │ 截图(按需)         │ 搜索结果          │ 情绪标签
                                                │                    │                   │
   ┌─────────────┐   ┌──────────────┐   ┌───────┴──────┐   ┌────────┴───────┐   ┌───────▼────────┐
   │ 情绪识别     │   │ 多模态输入    │   │ 本地小视觉    │   │ SearXNG + MCP  │   │ THA 桌宠(本地) │
   │ 文字+SER(VAD)│   │ 截屏+音频截取 │   │ 看屏(按需)    │   │ 免费联网(可选) │   │ 情绪→pose 表情 │
   └─────────────┘   └──────────────┘   └──────────────┘   └────────────────┘   └────────────────┘
        本地轻量            提问时打包          本地GPU(小)          本地服务             本地GPU
```

**一句话**：本地 GPU 只背 THA(画面) + 按需的小视觉模型；对话主力走云端/远程；联网搜索用免费自托管 SearXNG(MCP 工具)；情绪识别走文字+语音轻模型。全部作为主力模型的外挂能力，职责清晰、显存可控、成本可控。
