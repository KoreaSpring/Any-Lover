# 记忆与人格：桌宠长期记忆路线

> 目标：让 Any-Lover 桌宠不只是记住本次对话，而是形成对用户的持续认知、关系演进、人格一致性——即"人格记忆"。
>
> 定位：与 `emotion-aware-companion.md`（情感闭环）强关联，二者合起来构成"有记忆、有情感、人格稳定"的陪伴大脑。属方案甲之后的进阶方向，分阶段落地，不阻塞主线。

---

## 1. 现状（基于后端实际代码）

上游 Open-LLM-VTuber 后端已有**基础记忆**，但能力有限：

| 机制 | 位置 | 能力 |
| --- | --- | --- |
| 会话内记忆 | `agent/agents/basic_memory_agent.py`（默认 agent） | `self._memory` 列表，把每轮对话平铺进上下文 |
| 历史持久化 | `chat_history_manager.py`、`conversations/` | 存磁盘（`chat_history/<conf_uid>/<history_uid>`），重启能续 |
| 长期记忆接口 | 配置里 `letta_agent`（默认关） | 预留接 Letta(MemGPT)，但需用户自建 server，门槛高 |

**短板**：本质是"把完整对话历史塞进上下文"——会话一长就 token 爆炸、变慢、超窗口。没有：
- ❌ 真正的长期记忆（跨会话提炼用户画像）
- ❌ 记忆摘要/压缩
- ❌ 语义检索（想起相关旧事）
- ❌ 关系演进 / 情感连续性 / 人格防漂移

> README「未来的她」已把"长期记忆与情感"列为规划方向（未实现）。本文档即该方向的设计。

---

## 2. 陪伴桌宠的"四层记忆"模型

陪伴记忆不该只堆一个框架，而应分四层：

```
1. 会话记忆     本次对话上下文            —— 现有 basic_memory 已有
2. 用户画像     长期事实：姓名/喜好/习惯/重要的人和事
3. 关系/情感状态 熟悉度/亲密度 + 用户情绪历史  —— 与情感闭环共享
4. 人格自我     桌宠自己的人设/说话风格，防漂移
```

第 2/3/4 层是"人格记忆"的核心，也是当前缺失、需要新建的部分。

## 3. 方案选型（调研结论）

### 通用记忆框架（2026 主流，可选接入）

| 框架 | 定位 | 适合 |
| --- | --- | --- |
| **Mem0** | 记忆"层"，从对话抽取事实回填 prompt | 个性化/偏好，集成最简单，社区最大 |
| **Letta**（原 MemGPT） | 记忆"运行时"，agent 用工具自编辑记忆 | 长期自主 agent；**后端已预留接口** |
| **Zep** | 时序知识图谱，记事实+"何时为真" | 需要时间推理 |

> 诚实提醒：这些框架厂商自报 benchmark（如 Mem0 自报 93%）与第三方独立测（开源版 ~32%）差距大，别轻信营销数字，需自测。来源：mem0.ai、dataaspirant、atlan 等公开对比（内容已改写以符合引用规范）。

### 专门的"陪伴人格记忆"思路（更贴合桌宠）

学术/社区 2026 有一批专解"人格一致性、情感连续性、关系演进"的工作，比通用框架更贴合：
- **人格漂移/崩塌（Persona Collapse）**：聊久了人设走样，需防漂移与校验。
- **情感连续性**：记住用户偏好 + 陪伴者人设 + 关系温度（如 ZifaMem: Persona+Preference+Emotional Continuity）。
- **关系演进**：per-user 关系随时间加深（如 Kaiacord：本地持久情感状态 + 每晚"记忆固化"把当天对话整理成长期记忆；如 Vela：从矜持到亲近）。
- 参考：Kaiacord、ZifaMem 论文、persona 图-向量混合记忆等公开项目（内容已改写以符合引用规范）。

## 4. 推荐路线：自建轻量为主，重框架为辅

**结论**：桌宠优先走**自建轻量方案**（结构化存储 + LLM 定期提炼 + 每日固化），而非一上来接 Letta 那种重运行时。理由：本地、隐私、无重依赖，符合桌宠定位；且和情感闭环天然融合（情绪状态就是关系记忆的一部分）。

### 渐进落地

| 阶段 | 做什么 | 方案 |
| --- | --- | --- |
| **A（最实用）** | 对话摘要压缩 + 结构化用户画像 | 定期让 LLM 提炼对话 → 存 JSON/SQLite → 注入 prompt。零重依赖 |
| **B** | 语义检索记忆（想起相关旧事） | 本地向量库（sqlite-vec / Chroma）+ RAG，或接 Mem0 |
| **C** | 关系演进 + 情感连续性 + 人格锚定 | 借鉴 Kaiacord/ZifaMem：关系状态机 + 每日记忆固化 + persona 校验 |
| **D（可选高级）** | 完整自主记忆 agent | 接 Letta（后端已预留 `letta_agent`，需另跑 server） |

### 存储与隐私

- 记忆数据**本地存储**（沿用现有 `chat_history/` 同级，新增 `memory/` 存画像/关系/摘要）。
- 用户可查看、编辑、清空记忆（透明可控）。
- 若记忆提炼调用云端 LLM，需告知用户对话摘要会发往其配置的 LLM 提供方。

---

## 5. 与情感闭环的关系

- **情绪状态 ⊂ 关系/情感记忆**：`emotion-aware-companion.md` 里识别出的用户情绪，既即时驱动语气/表情，也沉淀为"关系记忆"（如"用户最近常显疲惫"）。
- 记忆 + 情感 + 人格锚定合起来，才是真正的陪伴：记得住你是谁、你们聊过什么、这段关系什么温度，且桌宠自己人设稳定不漂移。
- 建议：情感闭环（第一步文字情绪）与记忆阶段 A（用户画像）可并行起步，二者共用同一份"用户档案"存储。

## 6. 关于外部记忆工具的说明（记录）

调研过程中评估过 `@1memory/cli`（"跨设备 AI 记忆"）：经审查它是给**编码类 AI 工具**（Claude Code/Codex 等）加记忆的，与**桌宠的用户记忆是两回事**，装了不会给 Any-Lover 增加记忆能力。且其核心为闭源二进制、云同步需数据上传第三方、会修改其他工具配置——**不采用**。桌宠记忆走本文档的自建路线。
